## 已确认的接口边界

接口复核阶段读取了机器人随 GDK 安装的官方文件，当时未运行运动命令：

- `build_dep/cpp/aarch64/include/common/types.h:558`：`EndEffectorPose`
  只包含 lifetime、group 和左右 EEF pose，没有夹爪字段。
- 同文件 `:947`、`:956`：`A2DTrajectoryAction` 同时具有 `right_arm` 和
  `right_effector`，轨迹请求带 `robot_link` 和 `trajectory_reference_time`。
- `build_dep/python/pybind/cpp/bind_robot.cpp:292`：Python
  `trajectory_tracking_control` 将两者放入同一个官方请求；前两个参数
  `infer_timestamp` 与 `robot_states` 被当前绑定忽略，不能靠填它们修复状态初始化。
- `build_dep/cpp/aarch64/include/gdk/robot.h`：本次检查的公开 Robot API
  未提供单独释放 legacy EEF 发布者控制权的 stop/release 方法。

以上路径均相对机器人 `/home/agi/app/gdk/`。声明说明接口能表达哪些命令，
不构成当前固件能够平顺跟踪这些命令的证明。

既有交接总结记载同进程、多线程或暂停 legacy arm tick 未解决独立工具接口不响应；
本轮未找到这三种尝试对应的原始 trace，因此不把这项总结当作本轮重新验证的结论。
已有原始证据明确显示 mux 停掉 arm child、等待工具反馈、重启并重新标定后才续跑。
2026-09-07 15:08 的 `hw_bridge_report_20260907_150822.json` 中，一次开爪行阻塞
10.3816 秒，观察到运动前等待 4.2131 秒，实际开爪约 0.5137 秒。配套 mux 日志
显示新进程 PID 和重新标定。这些文件在
`agibot/local_reports/xichong_right_place_runtime/gripper_bridge_hw_20260907/`。
这段无响应期的内部原因尚未证实；删掉等待、合并 Python 文件或只看 SDK 返回 0，
不能证明它已经消失。

## 联合路径测试前的问题与假设

优先核实官方联合轨迹路径在本机的初始化、参考坐标和时序要求，使它能稳定执行
“当前 EEF＋保持夹持目标”。2026-09-08 17:09 的测试已经补上当前 link3 参考姿态，
仍在 7 次请求后下移 1.513 mm，随后总下移约 2.584 mm。测试未运行模型，故应先
定位联合接口的跟踪问题；现有证据不足以认定是 Python 映射、负载参数或 GDK 缺陷。

原始记录在
`agibot/local_reports/xichong_right_place_runtime/native_retest_20260908_1710/RESULT.md`。
其中官方日志的 `real dt`、`last traj abort`，以及更早的默认机器人参数加载记录
是待核实线索，不能当作已证实原因直接改频率、参数或补偿。

如安装文档无法解释这些行为，需要 GDK 支持方针对本机软件版本确认：

1. 同一个 Robot 同时使用 legacy EEF 和工具接口是否受支持，是否有公开的无重启调用方式。
2. 联合 `ABS_POSE + ABS_JOINT` 在本机的推荐启动流程、坐标/参考语义、控制周期和固件配套。
3. 原地目标仍下移以及轨迹被反复替换的日志是否符合预期；若否，所需官方修复或配置是什么。

当时计划先验证联合路径的反馈跟踪，再接入已有官方 GR00T runner 的延迟激活和
执行回执协议，用同一时间线执行 EEF 与夹爪。下文记录本次验证的实际结果。
legacy 版本仍保留为可恢复的基线；不会在运行中自动切回。

### 完整 GR00T 运行结果（14:21）

本地证据目录：`agibot/local_reports/continuous_control_20260909/full_7tou1x/`。
包含 `inference.json`、联合服务 `action.log`、通过的 `closed_hold_roundtrip.json`，
以及 `before/` 和 `during/` 双相机照片。`during/` 实际是在完整 runner 结束后采集，
不是同步过程录像。最初失败记录保留在相邻 `hardware_RklaZX/` 目录。

使用任务 checkpoint-30000 和官方 GR00T policy 服务；单个联合服务负责右臂与夹爪。
先加载/预热模型，再激活一次控制器；本次完整运行标定结束位置误差约 0.057 mm。

- 3 个 H16，48 条模型行全部取得成功执行回执，每行 5 个联合控制 tick。
- 正式模型调用耗时依次约 0.323 / 0.300 / 0.315 秒，不含首次预热。
- 48 条回执记录的行执行耗时范围 98.4–108.4 ms；各行最后一次 SDK 调用间隔

- 第 3 块第 9 行记录真实开爪反馈 `-0.73598 rad`，最终为 `-0.78073 rad`；
