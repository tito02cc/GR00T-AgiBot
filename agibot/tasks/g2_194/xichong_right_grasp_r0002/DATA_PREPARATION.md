## 转换语义

| 项目 | 转换约定 |
| --- | --- |
| 输入图像 | `head_color`、`hand_right`，640×480，10 Hz |
| 状态 | 右末端 XYZ + Rot6D + 右夹爪，共 10 维 |
| 原始动作 | `next_delta`：base_link 世界坐标平移增量、世界坐标旋转向量、下一步夹爪绝对值 |
| Parquet 动作 | 下一步绝对 XYZ + Rot6D + 夹爪；不是直接把单步增量拼成 H16 |
| XYZ 重建 | 当前 XYZ + 原始平移增量 |
| 姿态重建 | `R_target = Exp(delta_rotvec) @ R_current` |
| Rot6D | 旋转矩阵前两行展平，与本仓库 GR00T EEF 实现一致 |
| 夹爪 | 保留原生弧度值，约 −0.785 为张开、接近 0 为闭合；不是米，也不是 0/1 二值标签 |
| GR00T 动作处理 | 官方 processor 将 H16 绝对 EEF 目标变换为相对于窗口当前状态的动作；夹爪保持绝对表达 |
| 归一化 | 本次训练集统计，`minmax`，正式训练须使用 `--no-use-percentiles`，留出集不参与拟合 |

H16 对应 10 Hz 下 1.6 秒动作块。每个保存帧均保留，视频/Parquet 使用相同的固定 10 Hz 时间网格。
采集时钟的实际 `timestamp_monotonic` 另外保存在 `meta/source_episode_map.json`，不冒充严格无抖动采样。
训练 processor 自身仍有越界裁剪；转换阶段没有裁剪原始值。验证报告单独记录归一化越界比例和影响。

## 图像编码

沿用已使用的 H.264、CRF18、fast、yuv420p。该步骤是有损编码，并不等于无损打包；
原始 JPEG 没有被覆盖。每帧的数量和顺序不变，验证时对全部解码视频帧与对应 JPEG 比较。
最低逐帧 PSNR 要求 30 dB，用于发现明显编码/帧对应问题；该指标不能保证模型效果完全不受压缩影响。

## 自动验证与产物

配置与脚本全部在本任务目录，输出只写入 `prepare.json` 指定的位置。
`prepare.py` 复用旧流程的通用格式转换函数，不调用旧放置任务的准入审核函数。

- `local_raw_audit.json`：本地数值、合同、图像复核与警告。
- `conversion_summary.json`：训练/留出条数、帧数及输出目录。
- `train_conversion_audit.json`、`heldout_conversion_audit.json`：全部 Parquet 与全部视频帧验证。
- `official_loading_and_math.json`：官方 episode loader、状态动作 processor、完整 H16 窗口数学往返、训练统计量复核及越界诊断。
- `preparation_status.json`：当前阶段或错误；最终通过标记为 `AUTOMATED_DATA_CHECKS_PASS`。
- 各数据集 `meta/`：模态、任务语言、episode 源映射、统计量及归一化来源。

`initial_pose_reference.json` 只是最接近训练起始分布中心的一条实际训练起点，**不是机器人复位命令**。
相机与状态的采集同步精度受原始采集系统限制，转换只保持对应关系，不虚构硬件同步。
这里验证的是数据与处理数学，不加载策略权重，不执行训练，也不移动机器人。

## 复现与失败处理

从仓库根目录运行 `prepare.py`，默认包含清洗复核、转换、统计、验证四阶段。
`--stage convert` 只转换；`--stage verify` 对已生成的两组完整数据重新计算训练统计并验证。
若原始复核不通过，应看报告定位问题，保留源文件和名单，不自动套用别的任务筛选策略。
若转换中途退出，应保留失败日志，另设输出目录重新运行；脚本不会自动覆盖半成品。

数据检查完成后，训练前还需单独核对 base model、正式训练配置和实际 GPU 上的前向/反向运行。
不能把数据准备通过写成“模型必然训练成功”或“真机可直接运行”。
